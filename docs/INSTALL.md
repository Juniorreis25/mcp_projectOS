# Installation and validation

Requires Node.js >=22 and npm >=10.

## Clean install
```bash
npm ci
npm run check
```

The committed package-lock.json is required. The first lockfile is generated by the dedicated manual GitHub Actions workflow `Bootstrap F1 lockfile` and verified by `F1 checks`.

The MCP app has its own lockfile at `apps/mcp-server/package-lock.json`. From the repository root, run `npm ci` for the core checks and `npm ci --prefix apps/mcp-server` for the server.

## Validation
- `npm run lint` uses TypeScript AST checks for explicit any, debugger, console.log, TypeScript suppression directives and tabs. This is a project-specific quality gate, not ESLint.
- `npm run typecheck` performs strict TypeScript typechecking.
- `npm test` builds and runs Node's automated tests.

## MCP server validation
```bash
cd apps/mcp-server
npm ci
npm run typecheck
npm run build
npm test
```

`npm test` starts the built server with a test token and checks health, MCP initialization, tool discovery, both catalog operations, authentication rejection, manifest-backed instructions, and path-traversal rejection.

## Vercel
Use `apps/mcp-server` as the Vercel Root Directory and set `PROJECTOS_MCP_TOKEN` only in the Preview environment. The token is a personal pilot credential, not OAuth or per-user authorization. The verified preview URL and remote checks are recorded in `PROJECTOS_PLAN.md`; do not promote it to production without explicit approval.
